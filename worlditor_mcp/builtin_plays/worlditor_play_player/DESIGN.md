## 0. 一句话

**玩家要一个"壳层 + 一个全屏个人页"：页眉常驻基础信息；页眉右侧抽屉是第一个挂载点
（玩法包往里放「我」）；「我」是全屏页，内部底栏是第二个挂载点（玩法包往里放背包/技能）；
属性页是第三个挂载点（玩法包往里放自己的属性）。**

**关键结论（现状版）**：

| # | 结论 |
|---|---|
| 1 | 三个挂载点里**只有壳层挂载点需要新机制**——它已经做完了（K-1 / D52）。另外两个用现成的 `ui_hook`。 |

### 1.6 概念对齐：视图 vs 挂载点

**视图（view）** = 一个包提供的前端组件 + 一个 key。

```python
register_view("player", title="我", icon="🙋", provider=..., layout="fullscreen")
```

内核记在引擎里（`engine.py:1392`），`GET /views` 列出来（`http.py:520`），壳层按 `layout`
分流：`default` 进顶栏 tab，`fullscreen` 不进 tab、占满 `<main>` 并隐藏页眉。

**挂载点（mount point）** = 一个"别人可以往里放东西"的命名位置，四要素：
名字（块 kind）、归属（内核 / 某个包）、内容协议（`UiBlock` 列表 / 视图引用）、渲染规则。

| 挂载点 | 归属 | 内容协议 | 现状 |
|---|---|---|---|
| 顶栏 tab 条 | 内核 | 视图引用 `{key,title,icon,url,layout}` | ✅ `register_view` |
| 页眉抽屉列表 | 内核 | `UiBlock` 列表 | ✅ **K-1 / D52** |
| 「我」的底栏 | **玩家包** | `UiBlock` 列表 | ✅ 机制够（`ui_hook`），包未写 |
| 「我」的属性页 | **玩家包** | `UiBlock` 列表 / 自动渲染 | ✅ 同上；**默认走自动渲染**（§10.2） |

### 3.1 K-2 的语义比原计划更保守（重要）

原计划只写"加一个深度熔断"。**实际实现多了一层"钩子身份去重"**：

- `spent` = 沿当前展开路径**已经应用过的 `(块 kind, 位置, play_id)` 集合**（`engine.py:2002` 起）
- 同一个钩子在**同一条路径**上最多应用一次
- 深度上限 `_UI_HOOK_MAX_DEPTH = 32`（`engine.py:334`）仍保留，作兜底

**为什么必须这样**：`spent` 只挡"同一条路径重复命中"，**不挡合法的同 kind 嵌套**（原树的
子块共享同一个 `spent`、不新增条目）。所以：

- ✅ 装备包注入装备栏 → 饰品包 hook 装备栏 → **可以**（K-2 的初衷）
- ❌ A 的 `after` 钩子返回一个同 kind 的块 → **不会无限递归**

⚠️ **这是行为变更**：注入进去的块**不再是叶子**。v0.9.0 之前"注入块不展开"顺带当了一道
意外的护栏，现在护栏是显式的。

### 3.2 K-3 最后没走 `/scene`，走了 `/where`

| | 原计划 | 实际 |
|---|---|---|
| 做法 | `_build_scene` 补 `map_name`（约 2 行） | 新开 `GET /where` |

**为什么改了**：页眉要的是**世界 + 地图**两个名字（原计划只想了地图），而 `/scene` 是
"场景视图"的数据，混进页眉专用字段会把两件事绑死；而且 `/scene` 缓存语义与页眉的
"装饰信息"不同。**`/where` 更小、更专用、失败也不影响主区**（`App.vue:212` 只 `console.warn`）。

### 3.5 K-11 显示名校验（v0.9.1 补上的那一笔）

**背景**：K-7 让 `core:info` 可直写（否则玩家包改不了名），但 Q-5 定的
"长度 / 控制字符 / 双向文本归内核"一直没实现——文档却写着"已定"。补上了。

**规则**（`model.check_display_name`，只做四件事）：

| 做什么 | 细节 |
|---|---|
| 去首尾空白 | `"  张三  "` → `"张三"` |
| 拒空 | 全空白 / 非字符串 → 报错 |
| 限长 | `DISPLAY_NAME_MAX = 24` 个**字符**（中文按 1 计） |
| 拒"会改变显示效果"的字符 | Unicode 类别 `Cc`（换行/制表等）、`Cf`（**双向控制符** `U+202A–202E` / `U+2066–2069`、**零宽** `U+200B–200D` / `U+FEFF`）、`Zl` / `Zp`（行段分隔符） |

**唯一放行的 `Cf` 是 ZWJ**（`U+200D`）——否则 👨‍👩‍👧 / 👩‍💻 这类 emoji 序列全废。代价已记录：
ZWJ 仍可用于"零宽冒充"，但同形字（西里尔 `а` 冒充拉丁 `a`）内核本来也挡不住，
挡一个不挡另一个是安全剧场（D49 的原话：内核"只保证不污染内核文案，不保证名字是真的"）。

**六个写入出入口全部接上**（这是 K-11 的核心，少一处就等于没做）：

| # | 入口 | 落点 |
|---|---|---|
| ① | 字段写 `set_data` | `_set_data_default` → `validate_core_field` |
| ② | 同上，**玩法包那条门** | 同一条路径（`core:` 跳过玩法包原语表，D33 → 包绕不过去） |
| ③ | 整块写 `set_component` | `_set_component_default` → `validate_core_payload` |
| ④ | 建组件 `add_component` | `_add_component_default` → 同上 |
| ⑤ | 管理端 `update_entity` | `name=` 与 `components=` **两个入口都校验** |
| ⑥ | 创建 `place_entity` / `import_bundle` | `_compose_entity` → 显式 `name` 走校验 |

**两条刻意的边界**：

1. **`desc` 不校验**——描述本来就是多行长文本
2. **组件 `label` 派生的名字不校验**——那是**作者数据**，不是玩家输入；否则一个起了长
   label 的包会让 `place_entity(kind=…)` 突然全失败，而报错指向的地方跟它无关

**不做**：同形字 confusables 表（成本 >> 收益）、重名检查（Q-5 已定用 id 区分）、
NFKC 归一（会改写用户输入）。**冷却仍在玩家包**（那是玩法规则）。

**回归**：`tests/test_display_name.py`（19 条：规则本身 + 六个入口 + 两条边界 + 中文/emoji 放行）。

### 11.1 三个必须先回答的技术问题（不然实现时会卡住）

**① "下线前位置"存哪？**

今天**没有任何内核代码会自动清位置**——`clear_position` 只有包会调（`api.py:475`）。
也就是说"下线"在数据上**根本没发生**：实体还站在原地。

→ 两个选项，**必须写下来，不能默认**：

| 选 | 做法 | 代价 |
|---|---|---|
| **A. 离场由玩家包做** | 订阅 `on_principal_logout`（D47）→ 把 `core:position` 存进本包 kv → `clear_position` | 多一套状态；**多端登录时一台退出会把化身弄下线**（`on_principal_logout` 是**凭据**被吊销时发的，别的设备可能还在线） |
| **B. 离线也站在原地** | 什么都不做 | 世界里有一具不动的身体（那是玩法选择，但不是"下线"） |

→ **2026-10-18 已定（第二版）：不做心跳**；空闲 = "最后一次操作"，下线策略玩家可配
（永不下线 / 15·30·60·180 分钟）。细节见 **§11.3 ①**。

**② "候选的出生点"从哪来？**

今天是 `data/spawn.json` 里**一个**点（`_pick_tile`）。"候选**们**"要有来源：
包内数据列几个（简单，全世界共用），还是内容作者在地图上摆（玩家包袱命名空间的组件，
才能做到"每张图有自己的出生点"）。**这条没定，上线界面就只有一个真选项。**

→ **2026-10-18 已定**：用法是"地图上摆实体 + 出生点组件"，**玩家自己选**（不自动取第一个）；
组件用玩家包自己的命名空间（`worlditor_play_player:spawn`，合法），见 **§11.3 ② / b**。
"家园"这类**个人出生点**将来用归属标记区分公共 / 私有，等家园包落地再定。

**③ 流程跑完去哪？**

玩家包的视图如果**全是 `fullscreen`**，顶栏 tab 条就是**空的**（`App.vue:137` 只收
非 fullscreen）。创建完 / 上线完落脚到哪？目前只能落到另一个 fullscreen 视图（「我」）
或空态。**"看世界"的视图属于第二个包**（D48）——所以全新安装的体验会是
"人能站住、但没地方可看"。**这条要确认是否可接受。**

### 11.2 验收标准（实现时照这个测）

- 全新账号登录 → 落在**创建流程**，不是字母序第一个视图
- 创建完 → 能正常看到世界（或明确知道去哪儿）

### 11.3 2026-10-18 讨论稿：1 玩家 = 1 化身，离场与恢复

> **设计已定，代码未落地。** 本节 = 玩家包的最终形态 + 已核对的内核事实。

**形态（你说的）**：

- 内置玩家包 = **1 个主体 = 1 具化身**；**多化身面不在本包**（框架能做，别的包去做，见 ③）；
- **下线** = 从地图上移除，但化身上的组件**完完整整保留**；
- **上线** = 回到玩家选的「上次下线位置」，或从几个**候选出生点**里挑一个；
- 候选出生点 = 地图上一个**带「出生点」组件的实体**；该组件由玩家包声明。

#### 内核已经准备好了三样（好消息）

| 要做的 | 现成机制 | 关键事实 |
|---|---|---|
| 离场，但实体还在 | `api.clear_position()` | 只摘 `core:position`；组件、标签、`core:account`、`revision` **原样留在实体上**（`engine.clear_position` 的 docstring 自称"D36 的**下线通道**"） |
| 回场 | `api.move_entity()` | **接受不在场的实体**（docstring 专门写了"把离线实体放回世界"，D36 放开的就是这条路径）；目标地块必须存在，否则 `WorldError("地块不存在")` |
| 离场后别人看不见他 | 默认查询 | `query_entities` / `list_entities` 默认 `include_absent=False` 按位置过滤——所以按位置的交互自然打空，不用另写判断 |

**推论：「把组件完完整整保存」不需要任何快照机制。** 只要**不用 `remove_entity`**，实体本来就一直躺在库里。
这条把最重的一块工程量消掉了——离场是"摘一个组件"，不是"序列化一具身体"。

#### 三条：两处已定、一处校正

**① ✅ 已定（2026-10-18，第二版）：不做心跳。空闲 = "最后一次操作"，下线策略玩家可配。**

心跳被否掉：要客户端定时打点、要一套新协议，而且 agent 根本不跑这个定时器。改成**被动记录**——
操作发生时顺手记一笔，没有操作就没有记录，比心跳少一整套东西。

- **打点位置**：MCP 工具入口 `_dynamic`（`mcp/__init__.py`）——**所有**工具调用都从这里过，
  而那里已经拿到 `entity_id`。打点 = 把**调用者实体的 `last_active_ts` 改成现在**。
  **复用现有字段**：它本来就注释着"在线状态（动作 / SSE 活动维护）"，只是从没人写；
  不新增存储、不新增 API。
- **什么算"操作"**：**只有工具调用**。`/state`、`/scene`、`/where` 这些读接口不算——
  否则开着页面看地图的人永远在线。**明确后果**：只开页面不操作，会被判空闲下线。
- **扫描**：玩家包 `on_tick`（5 分钟一轮，后台循环，不依赖有人在线）→ 按策略判断 →
  超时就把位置记进化身组件 → `clear_position`。
- **两条防误伤规则**：`last_active_ts == 0`（未知 / 刚重启）**不清人**——等下一次操作恢复，
  不会一启动就把所有人踢下线；策略读不到就用默认，不报错。
- **策略可配**：`永不下线`，或 `空闲 N 分钟后自动下线`。存**本包 kv、按主体**（"我希望被
  怎么处理"是人的偏好，不是某一具身体的属性）；默认空闲 30 分钟。
- **主动下线 ≠ 自动下线**：显式注销仍然**立即**离场（`on_principal_logout`），不看策略；
  `永不下线` 只关掉**空闲自动**下线。
- **上次位置**：存在**化身自己的组件**里（`worlditor_play_player:last_place`），随化身删除
  自动清理——存主体 kv 会留垃圾，多化身时语义也不对。

**代价**：一处内核打点（`_dynamic` 里一行 + 一个只写内存的小方法），**不落库**。
代价的代价：**重启后全员"未知"→ 自动下线暂时失效，直到各自下一次操作**。不追求灵敏，
这条接受（要补的话是"让打点顺带落库"，先不做）。

**恢复分两种，别混**：

- **主动下线后上线**（显式登录）→ 走上线界面：回上次位置 / 选出生点；
- **自动下线后的下一次操作** → **不打扰**：**先回上次位置，再执行这次动作**。
  玩家没有离开的意图，不该弹选择。
  ⚠ 为什么必须"先恢复"：位置清掉之后，别的包的 `move` 会因"不在世界上"直接失败
  （`engine` 里路径移动要求在场）——所以唤醒做成**玩家包挂在 `move` 上的原语过滤器**
  （`register_primitive_filter`，D11 现成机制）：要移动的是本包化身且不在场上 → 先
  `move_entity` 回 `last_place`，再把参数交给默认实现。**任何包的走路工具都会把人带回来**。
  其他动作（交互等）在唤醒前仍可能失败一次，靠 `player_whoami` 的提示兜住。

> 顺带一个**对 1:1 有利**的事实：登录时 `revoke_tokens_of_account` 会静默吊销旧凭据**且不发事件**
> （`identity.login` 注释："刷新凭据不是登出"）——同一账号本来只有一个活会话，
> 所以"多端登录互相把化身踢下线"的担心不成立。

**② ✅ 校正：就叫 `worlditor_play_player:spawn`（我上一条把三种"写"混成了一种）。**

#### f ✅ 已定（2026-10-18）：玩家包的组件一律用自己的包名

**结论：`local:avatar` → `worlditor_play_player:avatar`。** 玩家包不再使用 `local:`——
"能看到归属"比"省一个前缀"重要。三个组件因此是 `:avatar` / `:spawn` / `:last_place`。

**它是什么**：玩家包 `declare_component("local:avatar", label="化身")`，`_create` 造实体时带上它。
**全仓没有任何代码读它**——roster 走 `core:account`（D42），"是不是人"从不看它。所以它今天的
全部作用，是给编辑器 / 管理员看的一个标签。

**名字的问题**：

1. `local:` 看起来像"公共约定"，实际是**本包自己的概念**；键里看不出主人（D44 说归属的唯一
   事实来源就是键，`local:` 是那个例外）。
2. `local:` 人人可写，**别的包可以静默给你标 / 去标记**。今天没人读所以无害，但"谁算化身"
   多一个来源就是负债——真相只有 `core:account`。

| 选 | 做法 | 代价 |
|---|---|---|
| A 删掉 | 不再声明、不再写 | 编辑器少一个"这是玩家化身"的标签；将来要给它挂数据（外观等）得重建 |
| **B 改名（✅ 已选）** | `worlditor_play_player:avatar` | 一个常量 + 一处声明；**零读者、零真实用户**，不需要迁移；旧数据里的 `local:avatar` 会变成"虚构组件"（还在，只是没声明） |
| C 不动 | 保持 `local:avatar` | 零成本，但键在说谎，且永远可被别的包写 |

**为什么选 B**：docstring 原话就是"纯属本包自己的内容约定"——自己的约定就该用自己的命名空间。
改名后：键即归属、卸载可清、诊断里一眼看出是玩家包的东西。G65 若落地，守卫不再拦写，
但**声明归属与清理语义**仍然按键走，所以改名依然有意义。
