## 0. 一句话

**实体的数据组织形态 = 少量表面项 + 一个组件列表；组件里的东西不扒出来摊平。**

能力面（今天的 `kind` / `tags`）折叠成组件：组件名 = `source:name`，`source` = 声明它的玩法包。
身份（`kind == "player"`）这个概念**删掉**。

## 2. 决策清单（A1–A4 + B1，均已拍板）

### A1 身份彻底移除（不引入 `core:player`）

**为什么能做**：`api.py` 里**完全没有**身份的痕迹（`identity` / `player` 零命中）——
身份是纯粹的内核 + 管理端概念，删它**不动玩法包接口**。

| # | 今天的闸门 | 处置 |
|---|---|---|
| 1 | `remove_entity` 拒绝删身份实体（D14 红线） | **换判据**：改为"带 `core:account` 组件" |
| 2 | `delete_identity_entity`（注销的受控豁免） | **并入 `remove_entity`** |
| 3 | `move()` 只让身份实体走路径 | **删**（玩法域；`move_entity` 传送本来就不限身份，今天已经不一致） |
| 4 | `update_entity` 锁定身份实体的 `kind` | **删**（连带修掉已实测的"反向升格"洞：`update_entity(kind="player")` 能把普通实体升格成身份实体，之后 `remove_entity` 拒绝删除它） |
| 5 | `delete_map` 拒绝"图上还有玩家" | **换判据**：`core:account` |
| 6 | `copy_map` 不复制玩家实体 | **换判据**：`core:account` |
| 7 | `delete_location` 拒绝"这块地上有玩家" | **换判据**：`core:account` |

**关键**：5/6/7 三条真正想问的**都不是"身份"，而是"这个实体绑着账户"**。
换成 `core:account` 判据后**更准**：

- 今天一个 `kind="player"` 但没绑账户的实体也会挡住删图；一个绑了账户但 kind 不是
  `player` 的实体反而不挡
- 不是新概念：`identity_entity_of(account_id)` 本来就按 `core:account.user_id` 找，
  `delete_account` 也用它——**账户绑定才是那个真正起作用的事实**
- 落在 `core:` 命名空间里，玩法包写不了（D33），保护强度不变

**D14 红线的新表述**：**绑定了账户的实体，玩法包不可删除。**

**不做 `core:player`**：要在实体上打个"这是有人操作的"标记并不必要——token 的
`entity_id` 就是那个事实。

### A2 裸名解析（解析发生在**写入时**，落库键即最终键）

| 写入时的情况 | 落库的组件键 |
|---|---|
| 有**唯一**声明者 | `<那个包>:<名>` |
| **无人**声明 | `local:<名>` |
| **多个**声明者 | **报错**（歧义） |
| 解析不出来（形态非法） | **报错**（**不静默落 `local:`**——否则"看着对、其实没人认领"） |

同一套解析同时服务于输入与查询（人写的裸名与包写的全名走同一条路）。

### A3 "先手输标签、后装包"不再自动接上（**这不是问题，是修正**）

今天：实例标签是裸名数组，包注册的也是裸名 → **同一个字符串** → 先手输的标签在装包后
**自动获得能力**。这是"裸名同键"白捡的性质，不是设计过的保证。

折叠后：`local:中毒`（无人声明时的落点）与 `worlditor_play_bestiary:中毒` 是**两个不同的
东西**——跟 `fps:hp` / `moba:hp` 一模一样。**那只狼理应不会中毒**。

要做的只有两件（都不涉及代码逻辑）：

1. 改 `tests/test_entity_tags.py:350` 的断言（该测试**本意是测"规格缓存失效"**，
   "后装包生效"只是顺带断到的）
2. 文档写明这条语义

**不做**认领 / 改名入口：正常部署是"包先装、内容后建"，遇不到；真遇到了在编辑器里改个组件名。

### A4 删"跨组件摊平"与分类字段

**为什么该删**：摊平存在的前提是"字段声明挂在**多值**的标签上"。折叠后声明挂在一个精确的
组件键上——**一个字段只有一个家、一个地址**，没有东西需要合并，也没有东西需要裁决。

| | 处置 | 理由 |
|---|---|---|
| 跨组件摊平（`effective_fields_for(多个标签)` + 按字段名去重 + 顺序覆盖） | **删** | 前提消失 |
| 分类字段（`add_category_fields` / `_category_fields`） | **删** | 同一前提的产物；折叠后"一个分类字段该写进哪个组件"没有答案（`categories` 作为**选取分组**保留，那是好用的） |
| **单个组件自己的字段清单**（自身声明 + 别人用 `add_tag_fields` 追加的） | **留** | 这就是"组件声明"本身，也是跨包扩展的正当路径 |
| 前端 `FieldForm.vue:129` 的重复实现 + `homeOf` / `fallbackName`（猜落点） | **删** | 合并没了 → 漂移隐患没了 → 落点不用猜 |

**新增的唯一规则**：**同一个组件里同名字段声明两次 → 报错**（同一地址只能有一个声明，与跨包无关）。

编辑器随之变成"**按组件分组渲染**"：哪个组件声明了哪些字段，就画在哪一块里。
`capabilities()["fields"]` 的语义同步改成按组件分组。

### A5 卸载语义：**数据留下、行为消失、钥匙不变**

折叠后**不存在"同名标签"**：组件名自带来源（`pkg_b:duel`），所以卸载一个玩法包时：

| | 结果 |
|---|---|
| **组件（数据）** | **留在实体上**——卸载不碰实体数据（与现有立场一致：demo 世界包的 `teardown` 写着"已导入的世界数据不回收（数据归用户）"） |
| **行为** | 该包贡献的**一切注册**撤掉：interactions / 字段声明 / 事件 / 过滤器 / UI / 服务 |
| **键** | **不变**——`pkg_b:duel` 这个键装回去还是它，所以"**重装即恢复**"是**真的** |

> **B2 在这里被修正**：今天 D19 写的"卸载即恢复"是假的（规格是单槽、被后来者整个替换）；
> 折叠后"恢复"不再需要栈——**键稳定**就够了。今天那套"同名覆盖 + `_tag_owner`"一起消失。

**四象限诊断**（名字里带来源，所以卸载后依然看得出它是谁的）：

| 状态 | 判定 | 用户该做什么 |
|---|---|---|
| **active** | 有声明 + 世界启用了 | 正常 |
| **inactive** | 有声明 + 世界没启用这个包 | 去世界设置里启用 |
| **orphan（孤儿）** | **source 那个包没加载 / 已卸载** | 装回那个包就好了 |
| **fictional（虚构）** | `local:` 或从来没被声明过 | 它**本来就没有行为**，不是坏了 |

实现：`source = key.split(":")[0]`；孤儿 ⟺ `source not in ("local", "core")` 且
`source not in engine._play_apis`。**`_tag_owner` 那张表可以删**——归属从"另存一张表"
变成"读名字"。这也**顺带解决 C8**（今天停用一个包，标签显示成"未声明"，而真相是
"声明它的包没了"）。

**孤儿清理**：建议**做，但不自动**——管理端能列出孤儿组件（按 source 分组，如
"`pkg_b` 已不在：N 个实体带 `pkg_b:*`"），**删不删由人按下去**。与 D13 立场一致：
数据删除必须是操作者的显式动作。而且"装回包就恢复"意味着手里有牌，不必急。

**两个边界要写进文档**：
1. **包改名（`play_id` 变了）= 它的组件全成孤儿**（`play_id` 就是身份）
2. **"不再有行为"的准确范围**：撤掉的是该包贡献的一切**注册**，**实体数据一个字节不动**

### B1 写入边界（**本次只做最小步**）

| 命名空间 | 今天 | 本次定案 |
|---|---|---|
| `core:` | 只有内核能写 | **不变** |
| `<自己的 play_id>:` | 没人管 | 玩法包可写 |
| `<其他 play_id>:` | **没人管**（能直写别人的组件） | **拦：报错** |
| `local:` | 没人管 | **暂不收紧**（玩法包仍可写；夹具与文档例子不动） |

落点很小：`api.py:318 _guard_component` **一处**（7 个调用点共用：组件三原语、字段三原语、
`place_entity` 的 `components`）。

**声明期的跨包扩展仍然允许**：`add_tag_fields`（B 给 A 的组件加字段）——"扩展可以，但要留痕"。

> ⚠ `docs/PLAY_DEV.md:684` 那句"`local:` 留给编辑器 / 人手写"**暂缓执行**，文档需标注
> "当前玩法包仍可写 `local:`"。

## 3. 施工切分

### 2a：不改表结构、不作废库（风险最低）

1. **声明合并**：`register_entity_kind` + `register_entity_tag` → 一个"声明组件"的 API
   （旧名保留为别名，旧包零改动）
2. **解析层**：裸名 → 组件键（A2 规则），插在**只有 3 处**的裸名承载点：
   `_entity_specs`（能力并集）/ `_live_tags`（query 匹配）/ `capabilities`（诊断）
3. **归属进名字**：`_tag_owner` 那张表可以删（归属变成组件键的结构信息）
4. **身份拆除**（A1）+ **写入边界**（B1）+ **删摊平与分类字段**（A4）
5. **顺手修 C8**（见 §6）：停用包时**不再删规格**，改由 `capabilities()` 多看一条
   "该包是否已加载"——这样 `inactive_tags` 终于能表达**"这个包被停用了"**
   （今天表现为 `unknown_tags`"未声明"，而"包被停用"恰恰是最该被解释的那种没效果）
   → 折叠后由 **A5 的四象限**承担（active / inactive / **orphan** / fictional），
   `_tag_owner` 删除后归属直接读名字
6. **孤儿组件清单**（A5）：管理端能按 source 列出"包已不在"的组件，
   **不自动删**（数据删除必须是操作者的动作，D13）
7. **薄适配层**：`kind` / `tags` 两列暂时保留，读的时候折成组件键
   → 让 2a **能独立跑绿**，且不动数据

### 2b：改表（v11）

1. 删 `kind` / `tags_json` 两列 → **4 列**
2. 适配层删掉
3. 前端：`EntityManager` 的"类型 / 标签"两区 → 组件区；`TagPicker` → 组件选择器
