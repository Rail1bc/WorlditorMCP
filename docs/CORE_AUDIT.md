# 内核边界审查（零玩法包视角）

> 审查基线：v0.1.18（2026-09-15）｜决策与落地：**v0.2.0**
> 方法：以空的 `builtin_dir` + 空的 `plays_dir` 启动完整服务（真实双端口）实测，
> 叠加三路代码清点（数据/引擎层、协议/服务层、装配/前端层）。
> 复现脚本在本地工具目录 `.uitools/`（不入库）：`audit_no_plays.py`（API 层）、
> `audit_no_plays_ui.mjs`（界面层）。

## 1. 审查结论：剥掉全部玩法包，内核剩什么

**注册表全空**：kind=0、MCP 工具=0、视图=0、管理页=0、跨包服务=0、原语过滤器=0、原语覆盖=0。

**仍然完整可用**的部分：

| 层 | 能力 |
|---|---|
| 数据/引擎 | 地图·地块·连接·模板·实体 CRUD；`move` 原语（依赖地块 connections）；事件总线 + world_log + SSE；`AsyncRLock`；attrs/state/data；play_data KV；可见性；世界与文件夹树 |
| 身份 | 注册/登录/无密码注册/改密/登出/永久注销/邀请码/凭据吊销/read 围观者；新玩家自动获得实体 |
| MCP 通道 | 可握手（initialize + session）；**工具列表为空** |
| 管理端 API | 读端点全部可用；写端点（建图/地块/连接/模板/实体）全部可用 |
| 管理端界面 | 账户管理、邀请码、世界与地图、**地图编辑器**——完全可用 |
| 玩家端界面 | 只剩「登录/注册/围观者/退出/注销 + 空态页」 |

一句话：**零包状态 = 一台带地图编辑器与管理后台的多人世界服务器，但没有玩法**。
能力在（原语全通），通道不在（没有工具/界面把它交给玩家与 agent）。

## 2. 发现的问题

### 2.1 内容伪装成内核（v0.2.0 已修）

| 位置 | 问题 | 处置 |
|---|---|---|
| `store.py` 种子区 | 内核硬编码整张主题世界：41 地块（小镇广场/步行街/AstrBot大道/开源小区/迷雾森林）+ 布局特判 + 时区 + 3 个种子实体（商贩·阿福/告示牌/木门）+ 喇叭物品；"表空即播种"导致删光后重启复活 | **外置**为世界包 `worlditor_play_demo_world`；内核只建空的"默认世界" |
| `mcp/__init__.py` instructions | 面向所有 agent 的文案写死 `world_look/world_move/world_interact`（属 movement 包），零包时是空承诺 | **改为动态生成**：按当前工具集列出工具名；零工具时明确提示"未加载任何玩法包" |
| `engine.py` / `model.py` | 身份实体 kind 分 `player`/`agent` 两类，且判定逻辑重复（`IDENTITY_KINDS` 与 `is_identity` 各写一份） | **统一为 `player`**（人类与 agent 不区分）；`IDENTITY_KINDS` 权威定义在 `model.py`，engine 复用 |
| `engine.py` | `state["block_move"]`、`attrs["invisible"/"see_invisible"]` 字符串散落 | 提为协议常量 `STATE_BLOCK_MOVE` / `ATTR_INVISIBLE` / `ATTR_SEE_INVISIBLE`（model.py 导出） |
| `mcp/http.py` | `worlditor_tier` 只写不读（工具级授权全靠玩法包自觉） | **消费**：read（围观）档在工具调用入口直接拒绝，文案明确 |
| 包卸载 | 停用/卸载后，包注册的持久化物品定义残留（"幽灵物品"） | 注册时记录归属，卸载时内存 + 落库一并清理 |
| `identity.py` | 出生点 = "maps 表第一张图的 spawn"，玩法概念落在内核 | **暂缓**（见 §4 待设计）；无地图时改为给出可操作指引 |

### 2.2 体验/健壮性缺口（v0.2.0 已修）

| 问题 | 处置 |
|---|---|
| 管理端**没有安装玩法包入口**（只能启停/卸载），玩家端空态却指向"去管理端安装"——零包时无自助路径 | 新增 `POST /admin/plays/install`（zip 上传，含结构/体积/路径穿越/命名校验与失败回滚）+ 管理端「安装玩法包（zip）」按钮 |
| `AuthPage.vue` 登录后硬编码跳 `#/world`（内核只认 `#/view/<key>`）→ 有视图也可能先显示"没有任何视图" | 登录后清空路由，由 App 按 `/views` 决定默认视图；未登录不再预加载视图组件（避免 401 留下误导 toast）；错误 toast 4 秒自动消失 |
| 玩家端空态写死"管理端口（默认 6289）" | 文案泛化（端口可配），并提示"没地图先建一张" |
| **零包部署死锁**（收口时发现）：内核不再播种地图后，没有地图就注册不了账户 → 连管理员都进不了管理端去启用世界包 | 身份层放行：无地图时账户与凭据照常发放（`entity_id` 为空），登录不阻塞；世界就绪后登录/注册**自动补建** player 实体 |

## 3. 决策记录（用户拍板，2026-09-15）

1. **主题世界外置**：内容提取为**专门导入该地图的玩法包**（不留在内核）。
2. **instructions 泛化** + 零工具时明确提示（按审查建议执行）。
3. **移除 agent 类型**：只有一种 `player`——不论人类玩家还是 agent，**不区分**。
   注册通道保留（`/auth/agent-register` = 无密码自助注册，供脚本/agent 使用），
   但实体 kind、实体名（不再加 `AI·` 前缀）、凭据 kind 全部统一为 player。
4. **出生点语义搁置**：后续做"世界与地图治理"设计时再定；本轮只记录不改动
   （实现上仅把"无地图"的错误文案改为可操作指引）。

其余（P1/P2）按审查建议执行：安装闭环、`#/world` 死链、tier 消费、协议常量、
卸载清物品定义。

## 4. 待办（本轮未做）

- **出生点 / 世界与地图治理**（决策 #4）：目前 `_spawn_pos()` = 首张地图的
  `spawn_row/spawn_col`，不区分世界（`world.play_ids`）、不校验该格是否存在。
  需要与"世界 = 玩法包激活集合 + 数据边界"一起设计（例如：按激活世界选
  spawn、spawn 落到最近可用地块、多入口出生点）。
- **世界包的内容更新语义**：`worlditor_play_demo_world` 采用"地图已存在则整体
  跳过"（不覆盖用户改动）。将来若要支持"世界包升级/局部补齐"，需要版本化与
  差异合并策略。
- 审查中发现但未处置的次要点：`PUBLIC_PATHS` 用 `startswith` 匹配（未来新增
  路径可能误免认证）、`/plays/{id}/web` 前缀校验建议改用 `is_relative_to`、
  管理端多处裸 `int()` 会 500、`sys.modules` 卸载残留、`?token=` 会进日志。
